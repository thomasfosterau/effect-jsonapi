`Conformance` gains two spec-tier rules that probe `include` and `sort` on an endpoint that does not declare them, so the kit now guards the 400 the middleware answers there. `spec/query/include-unsupported-endpoint` sends `?include=` to a read endpoint whose query does not declare `include` (JSON:API 1.1 §Inclusion of Related Resources: "If an endpoint does not support the `include` parameter, it **MUST** respond with `400 Bad Request` to any requests that include it"). `spec/query/sort-unsupported-endpoint` sends `?sort=` to a list or related endpoint whose query does not declare `sort` and whose response is a resource collection (§Sorting: "If the server does not support sorting as specified in the query parameter `sort`, it **MUST** return `400 Bad Request`", a section that "applies to any endpoint that responds with a resource collection as primary data"). Each fails on any status other than 400, and on a 400 whose `source.parameter` names only other parameters; a 400 with no `source.parameter` passes with a note. Each skips, saying why, when the api has no endpoint of that shape. A server that silently ignored either parameter, and passed every rule before, now fails one.
