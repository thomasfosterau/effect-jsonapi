**`Conformance.Options` gains `skip` and `requestTimeout`, two ways to bound a run against a live server (#302).** `skip` is a list of rule-id prefixes to leave out, the complement of `only` and matched the same way (a plain string prefix of the id): `skip: ["spec/pagination/links-enumerate-collection", "spec/links/"]` leaves out the pagination walk and the link crawl. It removes rules from what `tiers` and `only` select, so a rule both `only` and `skip` name is left out, and a rule it leaves out is absent from the report, as one `only` does not select is. `requestTimeout` takes any positive `Duration.Input` and bounds each request the kit sends — the client's whole `execute`, a `retry` it wraps itself in included, and the reading of the body — with each redirect hop a request of its own. A request still unanswered then is interrupted (over `fetch`, aborted) and reads as a lost response: status `0`, with a transport error naming the timeout, which every rule treats as any other transport error and never as a redirect the kit did not follow. **This changes the default for every run:** `requestTimeout` defaults to thirty seconds, for `verify` and `verifyWith` alike, so a run that sets nothing now reads a request unanswered after thirty seconds as a lost response where it used to wait for as long as the transport did. `requestTimeout: "Infinity"` (or `Duration.infinity`) turns it off and restores the old behaviour; a duration that is not positive (zero, negative, `NaN`), or one `Duration` cannot read (e.g. `"1e3 seconds"`), is a defect. `skip` is unset by default, leaving out nothing.
