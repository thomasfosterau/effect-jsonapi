A `Conformance` rule that dies no longer loses the whole report. In 0.16.3 a defect in any one rule (a transport that throws, or a bug in the kit) failed `Conformance.verify` / `verifyWith` outright, so every other rule's outcome — and, with this release's write fixture, the `Report.writes` ledger of what the kit created and whether it was removed — went unreported. The rule now gets a new `Errored` outcome (`Conformance.Outcome` gains a fourth member, `{ _tag: "Errored", rule, message, defect }`), every other rule still runs and is reported in the suite's order, and `Report.writes` is still filled. That holds whether the rule dies inside its Effect or throws before returning one. Interruption is not turned into an outcome: it still stops the run. A write fixture that throws a value the kit can render is not a defect: a `create` or `update` that throws one skips the rules it would have driven, and a `cleanup` that fails with or throws one is recorded in `Report.writes` as `cleanup-failed`. One that throws a value the kit can't render (a revoked `Proxy`, say) is still reported as `Errored` until #271.

**Behaviour change:** before, a dying rule failed the whole run; now the run succeeds with an `Errored` outcome, so a caller who gates on `summarise(report).failed`, `findings(report)` or `_tag === "Failed"` passes silently. If you gate on `failed`/`findings` rather than `Conformance.assert`, also check `summarise(report).errored === 0`.

`format` prints such a rule first in its tier, marked `DIED` with the defect's message (an `Error` as `Name: message`, any other thrown value as itself; capped at 500 UTF-16 code units, a longer one ending in `…`; and `[unrenderable defect]` for a value that throws when inspected — a revoked `Proxy`, say — which still leaves the run complete), and adds `· N died` to the tier and summary lines when one did (a run in which nothing died prints as before); `summarise` gains an `errored` count. `assert` dies on the first `Errored` outcome — with a defect tagged `RuleDied` (match it with `Predicate.isTagged(defect, "RuleDied")`) carrying the rule's id, a message naming the rule and the defect, and the original defect as its `cause` — before looking at failures, so the gate stays as strict as when the defect killed the run.

A `switch` over `Outcome._tag` that relies on exhaustiveness needs an `Errored` case.
