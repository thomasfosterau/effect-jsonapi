**Behaviour change: documents that were accepted now throw.** The document builders' full-linkage check (`Handlers.data`, `Handlers.collection`, `Handlers.buildIncluded`, and the `Assemble` builders that route through them) now walks reachability from the primary data — the same walk the conformance kit's `spec/document/full-linkage` rule makes — instead of passing any `included` member that some resource in the document references. A document the builders accept with `checkLinkage` on therefore passes that rule on the document value they build (encoding drops relationship keys the resource does not declare, so a member reached only through an undeclared relationship can still fail it on the wire: #250). The walk is iterative, so a chain of `included` members tens of thousands deep is checked without exhausting the stack.

Two shapes that used to pass now throw the full-linkage error (whose message now reads "is not reachable from the primary data through resource linkage"): a cycle of `included` members the primary data does not reach — for example after an `onResource` transform strips the primary data's `relationships` — and a member whose only reference is from its own relationships. A member reachable only through a member that is itself unreachable is rejected too, however many hops on. If a handler starts throwing, the `included` it builds was never linked to its primary data: drop the unreachable members, or keep the relationships that reach them.
